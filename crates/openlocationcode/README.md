# openlocationcode

[![crates.io](https://img.shields.io/crates/v/openlocationcode.svg)](https://crates.io/crates/openlocationcode)
[![docs.rs](https://docs.rs/openlocationcode/badge.svg)](https://docs.rs/openlocationcode)

Open Location Codes, also called Plus Codes: short codes that name a place on
Earth. A full code such as `8FVC9G8F+6X` is derived from a latitude and
longitude, needs no registry, and can be written on a signpost or read over the
phone. The crate encodes a location, decodes a code back to the area it covers,
shortens a code against a nearby reference, and recovers a short code to its
full form.

Ten characters cover roughly 13 by 13 metres at the equator; eleven or twelve
narrow that further. Because the leading characters are shared with everything
nearby, a code can be written in its short form next to a known place, which is
what makes it usable as a street address.

## Example

```rust
use openlocationcode::{encode, decode, shorten, recover_nearest};

// Encode a point near Zurich to the default ten characters.
let code = encode(47.365590, 8.524997, 10).unwrap();
assert_eq!(code, "8FVC9G8F+6X");

// Decode it back to the area it stands for. A code names a rectangle, so the
// answer is its corners and its center.
let area = decode("8FVC9G8F+6X").unwrap();
assert!((area.latitude_center - 47.3655625).abs() < 1e-6);
assert!(area.latitude_high > area.latitude_low);

// Shorten it against a nearby point, then recover the full code from the short
// form and the same point.
let short = shorten("8FVC9G8F+6X", 47.365590, 8.524997).unwrap();
assert_eq!(short, "+6X");
assert_eq!(recover_nearest(&short, 47.365590, 8.524997).unwrap(), "8FVC9G8F+6X");
```

## What it does

- `encode(latitude, longitude, length)` produces a code of the requested length.
  Ten is the usual choice; a length above fifteen is truncated to fifteen, and a
  length below two, or odd and below ten, is an error.
- `decode(code)` returns a [`CodeArea`] with the corners and center of the
  rectangle the code covers, and the code's significant length.
- `is_valid`, `is_short` and `is_full` classify a string without decoding it.
- `shorten(code, latitude, longitude)` drops the leading characters a nearby
  reference point shares with the code, and
  `recover_nearest(short_code, latitude, longitude)` rebuilds them.
- `encode_integers` and `location_to_integers` expose the integer step, as the
  reference does, for callers that already hold the integer form.

The code alphabet leaves out the vowels and the easily confused letters, so a
code is unlikely to spell a word and a letter read off a sign is likely to be
outside the set rather than a different valid one.

## Data provenance

This is an independent implementation of the algorithm published by Google at
<https://github.com/google/open-location-code>, which is the reference; it
shares no code with it and has no dependencies. Every case in the reference's
own test data is replayed in `tests/`:

- `tests/fixtures/encoding.csv` — 302 encodings, checked through the integer
  step, which is exact; the degrees-to-code path agrees with the reference
  within the floating-point tolerance the reference itself documents.
- `tests/fixtures/decoding.csv` — 420 codes, each decoded to its four corners.
- `tests/fixtures/validityTests.csv` — 25 codes classified as valid, short and
  full.
- `tests/fixtures/shortCodeTests.csv` — 19 codes shortened and recovered.
- `tests/fixtures/fuzz.tsv` — 23,918 cases generated by
  `scripts/fuzz/openlocationcode/gen.py`: random strings, mutated codes,
  random coordinates, and their shorten and recover answers, each labelled by
  the reference. Replayed in `tests/fuzz.rs`.

`research/tools/verify_openlocationcode.py` reruns the four CSVs against the
reference, so the port and the fixtures cannot drift apart.

## Scope

The crate computes codes from coordinates. It does not look anything up: there
is no geocoding, no place names, and no network access.
