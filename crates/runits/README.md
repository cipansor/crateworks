# runits

[![crates.io](https://img.shields.io/crates/v/runits.svg)](https://crates.io/crates/runits)
[![docs.rs](https://docs.rs/runits/badge.svg)](https://docs.rs/runits)

Unit conversion: parse a quantity written as text and convert it to another
unit, from a table compiled in from [Pint](https://github.com/hgrecco/pint).

## Example

```rust
use runits::{Quantity, convert};

// A value and a unit written as text.
let mass = Quantity::parse("3.5 kg").unwrap();
assert!((mass.to("lb").unwrap().value() - 7.716).abs() < 0.001);

// The affine temperature scales carry their offset.
let boiling = Quantity::parse("100 degC").unwrap();
assert!((boiling.to("degF").unwrap().value() - 212.0).abs() < 1e-9);

// Compound units are parsed, not just named.
let speed = Quantity::parse("60 km/h").unwrap();
assert!((speed.to("m/s").unwrap().value() - 16.666).abs() < 0.001);

// A one-line conversion between two named units.
assert_eq!(convert(1.0, "m", "cm").unwrap(), 100.0);
```

The crate carries **365 unit definitions under 1020 names**, the whole of Pint's
`default_en.txt` and `constants_en.txt` that can be written as a vector over the
seven SI base dimensions. There is no network call, no file to load and no
database to build: a lookup is a binary search over a table that is already in
the binary.

## What it does

* **Parse** a quantity written as text: a number, then a unit expression. A
  number on its own is dimensionless; a unit expression on its own is a value
  of `1`.
* **Look up** a unit by name, symbol, prefix or plural. `kilometre`, `km`, `kPa`
  and `metres` all resolve, in the same order Pint uses: an exact name first,
  then a prefix, then a plural.
* **Convert** between any two units of the same dimension, including the affine
  temperature scales, where the offset matters.
* **Combine** units by multiplication and division, so `kg*m/s^2` and `N` are
  the same quantity.

## Scope

The table covers the units whose dimension is a vector over the seven SI base
dimensions. Two groups fall outside it:

* **The Gaussian and CGS-EM units** (`statC`, `G`, `Mx`, `statF`), whose
  dimensions carry fractional exponents such as `[length]^1.5`, and the
  quantities that depend on them. A vector of `i8` exponents cannot hold them.
* **The logarithmic scales** (`dB`, `Np`, `octave`), which are not a linear
  factor at all, so storing one as a factor would be wrong.

Both are known to the crate rather than absent: `unit("dB")` returns
`UnknownUnit::Unsupported`, not `UnknownUnit::Unknown`, so a real unit is never
mistaken for a typo. `ppi` is likewise the printer unit and not `pico` x `pi`.

The table is a snapshot of Pint 0.26.2, not a live link. It is regenerated by
`research/tools/gen_units.py`, and `research/tools/verify_units.py` checks every
name against the Pint library itself, so a silent change upstream fails the gate
rather than drifting.

## Correctness

The table is not trusted on its own. `research/tools/verify_units.py` builds
Pint's own `UnitRegistry` and compares the factor, the seven dimension exponents
and the offset of every name. The result is written to
`tests/fixtures/pint_units.tsv`, which the test suite replays against the crate:

```text
pint unit names      1060
compared             973
mismatches           0
not covered          87
    59  known but outside the seven SI base dimensions
    28  pint-internal offset-difference unit, absent from the files
```

Every name the crate does not resolve has a reason that is checked against
Pint's data, so coverage cannot shrink quietly, and the gate exits non-zero if a
name ever resolves by prefix decomposition when it should not.

## Data provenance
