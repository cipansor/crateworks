# runits

[![crates.io](https://img.shields.io/crates/v/runits.svg)](https://crates.io/crates/runits)
[![docs.rs](https://docs.rs/runits/badge.svg)](https://docs.rs/runits)

Unit conversion: parse a quantity written as text and convert it to another
unit, from a table compiled in from [Pint](https://github.com/hgrecco/pint).

## Example

```rust
use runits::{Quantity, convert};

// A value and a unit written as text.
let mass = Quantity::parse("3.5 kg").unwrap();
assert!((mass.to("lb").unwrap().value() - 7.716).abs() < 0.001);

// The affine temperature scales carry their offset.
let boiling = Quantity::parse("100 degC").unwrap();
assert!((boiling.to("degF").unwrap().value() - 212.0).abs() < 1e-9);

// Compound units are parsed, not just named.
let speed = Quantity::parse("60 km/h").unwrap();
assert!((speed.to("m/s").unwrap().value() - 16.666).abs() < 0.001);

// Quantities of the same dimension add and subtract, in the left unit.
let total = Quantity::parse("3.5 kg")
    .unwrap()
    .add(Quantity::parse("500 g").unwrap())
    .unwrap();
assert!((total.value() - 4.0).abs() < 1e-9);

// A one-line conversion between two named units.
assert_eq!(convert(1.0, "m", "cm").unwrap(), 100.0);

// A logarithmic scale is a ratio to a reference, so 0 dBm is one milliwatt.
let power = Quantity::parse("30 dBm").unwrap();
assert!((power.to("W").unwrap().value() - 1.0).abs() < 1e-9);
assert!((Quantity::parse("1 W").unwrap().to("dBm").unwrap().value() - 30.0).abs() < 1e-9);
```

The crate carries **365 unit definitions and 7 logarithmic scales under 1066
names**, the whole of Pint's `default_en.txt` and `constants_en.txt` that can be
written as a vector over the seven SI base dimensions. There is no network call,
no file to load and no database to build: a lookup is a binary search over a
table that is already in the binary.

## What it does

* **Parse** a quantity written as text: a number, then a unit expression. A
  number on its own is dimensionless; a unit expression on its own is a value
  of `1`.
* **Look up** a unit by name, symbol, prefix or plural. `kilometre`, `km`, `kPa`
  and `metres` all resolve, in the same order Pint uses: an exact name first,
  then a prefix, then a plural.
* **Convert** between any two units of the same dimension, including the affine
  temperature scales, where the offset matters.
* **Combine** units by multiplication and division, so `kg*m/s^2` and `N` are
  the same quantity.
* **Convert a logarithmic scale**: `dB`, `Np`, `octave`, `decade` and the power
  ratios `dBm`, `dBW` and `dBu`. A logarithmic value is a ratio to a reference,
  so `0 dBm` is one milliwatt, `30 dBm` is one watt, and `1 Np` is
  `8.686 dB`. Converting between two logarithmic scales goes through the shared
  reference.
* **Add and subtract** quantities of the same dimension. The right operand is
  converted into the left one's unit and the result keeps that unit, which is
  what Pint does: `3.5 kg + 500 g` is `4 kg`, and `1 m - 25 cm` is `0.75 m`.
  Adding two different dimensions, or any affine scale such as `degC`, is an
  error rather than a silently wrong number. Adding two logarithmic values adds
  their logarithms, so `3 dB + 3 dB` is `6 dB`.

## Scope

The table covers the units whose dimension is a vector over the seven SI base
dimensions, plus the logarithmic scales whose reference does. One group falls
outside it:

* **The Gaussian and CGS-EM units** (`statC`, `G`, `Mx`, `statF`), whose
  dimensions carry fractional exponents such as `[length]^1.5`, and the
  quantities that depend on them. A vector of `i8` exponents cannot hold them.

Those are known to the crate rather than absent: `unit("statC")` returns
`UnknownUnit::Unsupported`, not `UnknownUnit::Unknown`, so a real unit is never
mistaken for a typo. `ppi` is likewise the printer unit and not `pico` x `pi`.

A logarithmic scale is not a linear factor, and the crate never treats it as
one. `unit("dBm").factor()` is the reference's own factor (one milliwatt,
`0.001` kg, which is `1.0` in the crate's gram-based units), and the value
converts through `reference * base^(value / divisor)`. Multiplying or
dividing a logarithmic quantity is refused, as is adding one to a linear
quantity, because `0 dBm + 1 mW` has no meaning; Pint refuses both too. A
logarithmic scale takes no SI prefix, so `unit("mdB")` is
`UnknownUnit::Unsupported` rather than a milli-logarithm.

The table is a snapshot of Pint 0.26.2, not a live link. It is regenerated by
`research/tools/gen_units.py`, and `research/tools/verify_units.py` checks every
name against the Pint library itself, so a silent change upstream fails the gate
rather than drifting.

## Correctness

The table is not trusted on its own. `research/tools/verify_units.py` builds
Pint's own `UnitRegistry` and compares the factor, the seven dimension exponents
and the offset of every name. The result is written to
`tests/fixtures/pint_units.tsv`, which the test suite replays against the crate:

```text
pint unit names      1060
compared             973
mismatches           0
logarithmic compared 13
logarithmic mismatch 0
not covered          74
    46  known but outside the seven SI base dimensions
    28  pint-internal offset-difference unit, absent from the files
```

Every name the crate does not resolve has a reason that is checked against
Pint's data, so coverage cannot shrink quietly, and the gate exits non-zero if a
name ever resolves by prefix decomposition when it should not. The logarithmic
scales are compared on their base, divisor and reference rather than on a linear
factor, and `tests/fixtures/pint_log_units.tsv` pins the 13 of them.

Arithmetic has its own oracle. `research/tools/gen_units_arithmetic.py` asks
Pint to add two quantities and records the number it returns in the left
operand's unit, which is the unit Pint keeps. The 1,378 rows in
`tests/fixtures/pint_arithmetic.tsv` cover every dimension the crate knows,
magnitudes from micro to mega, the four dimensionless logarithmic scales, and
121 pairs Pint refuses or turns into a unit neither operand named - a dimension
mismatch, an affine scale such as `degC`, or two dimensioned logarithms such as
`dBm` - where the crate must refuse them too. `tests/pint.rs` replays each row
as both a sum and a difference, so the two operations are pinned by the same
corpus.
